# SkyFlipper
Code that finds flipable items in Hypixel skyblock.
Powers the result of https://sky.coflnet.com/flipper 
 

Configuration can be found in `appsettings.json`.
You can overwrite it via Enviroment variables. 

> **Note**: the keys represent the JSON path of a value and `:` has to be replaced with `__`. eg `TOPICS:FLIP` becomes `TOPICS__FLIP`

## Auction archive

Closed months of MariaDB auctions are archived as immutable blobs in R2 (`AuctionArchiveJob`) and, once verified and old enough, deleted from MariaDB (`AuctionRetentionWorker`). Code in `Services/Archive/`, blob format and index tables in the core library (`dev/Archive/`).

**Blob layout** (bucket `S3:BUCKET`, Brotli compressed MessagePack, content type `application/x-msgpack+br`)
- `auctions/v2/{tag}/{yyyy-MM}/{part:D3}.msgpack.br`: `ArchivedAuctionBlock`, the auctions of one tag that ended in one UTC month, at most `MAX_ROWS_PER_PART` rows per part, raw item bytes, bids, enchantments, nbt lookups, coop and claimed bidders included.
- `auctions/v2/{tag}/index.msgpack.br`: `ArchivedTagIndex`, the verified months of the tag (parts, rows, sold rows, sha256 per part).

**Tables** (`ArchiveContext`, same database, own migrations history `__ArchiveMigrationsHistory`, created by the job on start):
- `auction_tags(id, tag)`, `auction_locations(uid → tag_id, month, part)`, `auction_bidders(bidder_id, end, uid)`, `auction_sellers(seller_id, end, uid)`: permanent indexes, never deleted. All of them are `PAGE_COMPRESSED` (zlib; needs ext4/xfs hole punching, `innodb_compression_algorithm=zlib` is the production default) and `auction_bidders` has no `amount` column: bid amounts come from the archived auction blob. `auction_sellers` has the same shape as `auction_bidders` (`seller_id` = `Players.Id` of the auctioneer, one row per auction, sold or not; unknown/anonymised sellers get no row). `auction_seller_backfill(month, done_at)` marks the months the R2 seller backfill finished.
- `archived_months(tag_id, month, ...)`: one row per verified tag-month; `tag_id = 0` is the month sentinel (`archived_at`: every tag archived, `deleted_at`: MariaDB rows deleted). `month` is months since 2019-01.

**What is archived and how**
- No items service and no id-to-tag map is used. Every `Auctions` row carries its own `Tag`; `ItemId` is only the index key. Once per pass `SELECT DISTINCT ItemId FROM Auctions` (loose scan on `IX_Auctions_ItemId_End`) lists the ids; each id is paged by `(ItemId, End)` per month. If that query fails the pass logs an error and writes no sentinel.
- The tag of a block comes from the rows: the rows of an ItemId are grouped by `row.Tag`. Edge cases:
  - one ItemId with several tags: each tag gets its own blocks;
  - several ItemIds feeding the same tag-month (ItemId 0 rows carry real tags): part numbers of a tag-month run across all ItemIds in ascending ItemId order, so they land in distinct parts. A re-run after a crash repeats the same order and overwrites the same part keys with the same rows (no duplicate parts); the markers (`archived_months`, R2 tag index) and the sentinel are written only after all ItemIds are done, so a crashed month is redone from its start.
- A row with a null or empty `Tag` fails the month (the auction id is logged), no sentinel.
- The sentinel is written only when every distinct ItemId was paged and every part verified. The retention worker deletes row by row only if the row's tag has a verified `archived_months` row for the month (`index_rows = rows`) and the uid is in `auction_locations`; an unarchived ItemId therefore blocks the month.

**Config**
- `S3:ENABLED`, `S3:ENDPOINT`, `S3:REGION`, `S3:BUCKET`, `S3:ACCESS_KEY`, `S3:SECRET_KEY`, `S3:USE_PATH_STYLE` (same as SkyBazaar; with an endpoint the region is only used for signing), optional `S3:CACHE_SIZE_BYTES` (default 256 MB).
- `ARCHIVE:ENABLED`, `START_DELAY_SECONDS`, `CLOSED_MARGIN_DAYS` (a month is closed 14 days after it ends), `OLDEST_MONTH` (default 2019-06, SkyBlock launch; raise it as the backfill completes months), `MAX_ROWS_PER_PART`, `PAGE_SIZE`, `CHILD_QUERY_BATCH_SIZE` (default 180, clamped to at most 199: MariaDB's `eq_range_index_dive_limit` is 200), `CHILD_QUERY_PARALLELISM` (default 6 concurrent child-table queries per page), `ITEM_PARALLELISM` (default 4 ItemIds of a month at once; replica connections are about `ITEM_PARALLELISM * (CHILD_QUERY_PARALLELISM + 1)`, MySqlConnector's default pool is 100; with more than one item part numbers of a tag follow completion order), `INDEX_WRITE_PARALLELISM` (default 1: index bulk inserts on the primary running at once across the parallel items), `INDEX_WRITE_TIMEOUT_SECONDS` (default 300: command timeout of the primary writes; a statement that still times out, deadlocks or hits a lock wait timeout is re-run up to 3 times after 2/5/15 s, counted in `sky_indexer_archive_index_write_retries_total`), `PAGE_PAUSE_MS`, `TAG_PAUSE_MS`, `MONTH_PAUSE_MS`, `IDLE_PAUSE_MINUTES`, `CHECKPOINT_TTL_HOURS` (default 48: finished ItemId-months are kept in the Redis hash `sky-indexer:archive:itemmonths:{yyyyMM}` so a restart skips them; cleared when the month sentinel is written).
- Retention: `ARCHIVE:DELETE_MARIADB`, `WINDOW_YEARS`, `MAX_DELETE_MONTHS_PER_DAY`, `DELETE_BATCH_SIZE`, `DELETE_PAUSE_MS`, `MAX_BINLOG_GB`, `MAX_HISTORY_LIST_LENGTH`, `REQUIRE_HEALTH_CHECKS` (the gate needs `SHOW BINARY LOGS` (`BINLOG MONITOR` or `REPLICATION CLIENT`) and reads `Innodb_history_list_length` via `SHOW GLOBAL STATUS` (no `PROCESS` privilege); without the binlog privilege nothing is deleted while this is true).

- Read replica: the archive job (reads only; `ArchiveContext` writes and the retention worker stay on the primary) uses `DBReadOnlyConnection` when set and non-blank, else `DBConnection`. Set `DBReadOnlyConnection` in the indexer's OpenBao secret (`kv/sky/sky-indexer`) to the replica and restart; the job logs which server it reads from at start. A child or page query that hits the statement timeout (MariaDB 1969) is split in half and retried (`sky_indexer_archive_child_query_retries_total{table}`) instead of failing the pass. `ARCHIVE__CHILD_QUERY_BATCH_SIZE` (default 180) should only be raised above 100 after `ANALYZE TABLE UuId` on the primary: `IX_UuId_SaveAuctionId` reports cardinality 2, so large IN lists otherwise full-scan.

**Seller index (`auction_sellers`) .** New archives write seller rows next to the bidder rows (`AuctionArchiveJob`: `Auctions.SellerId`, falling back to the resolved `AuctioneerId` when it is 0, because 0 is also set for duplicate players and on old unnumbered rows; `ScyllaArchiveImportWorker`: the auctioneer uuid of the Scylla parts, resolved to `Players.Id` with the same chunked lookup. Anonymised (`PlayerOptOut.AnonymousUuidPrefix` scheme), opted-out and unknown (no `Players` row) sellers get no row; both INSERT IGNORE). Months archived before the table existed are covered in the deletion pass, from the same read-back that verifies the parts:
- *Deletion pass, once per month, from the read-back.* Before the first MariaDB row of a month is deleted, `AuctionRetentionWorker` reads EVERY part of EVERY tag of the month once (uncached, so it is the decode that verifies the part against the R2 tag index, and the combined hash against `archived_months.sha256`) and INSERT IGNOREs the `auction_sellers` rows of every auction in it from that same decode: MariaDB-sourced parts, Scylla-only and merged parts alike (auctioneer uuid resolved in chunks of 100; anonymised, opted-out and unknown sellers get no row). A part is written only after its hash matched. Then the month's `auction_seller_backfill` marker is written; a hash mismatch, a missing part or an insert failure aborts the month with nothing deleted and no marker. The archive job and the import also write seller rows while archiving, but they never write the marker: items checkpointed before this deploy have none, so only this pass (whose rows come from the same decode; INSERT IGNORE dedups) marks a month. Every month goes through the pass once even when it has no MariaDB rows left (a Scylla-only month still has a sentinel, archived_months rows and a month in the loop; Scylla-merged months 2019-07..2021-03 are a subset of the phase-1 months 2019-06.. so none is outside the loop; months newer than `WINDOW_YEARS` are reached by the pass when they age out; until then only the archive-time rows exist, see the erasure note). Cost: one decode per part, throttled by `DELETE_PAUSE_MS` per part and capped by the daily month limit only for months that delete rows.
- *Per delete batch (safety net).* The batch's own `Auctions.SellerId` / `AuctioneerId` (a `SellerId` of 0 is resolved through `Players.UuId`, one bulk lookup per batch) are INSERT IGNOREd right before the batch is deleted; a failed insert aborts the month, nothing of the batch is deleted, the month stays open. `ArchiveContext` and `HypixelContext` share the `DBConnection` database, but values read with the batch are inserted instead of a cross-table `INSERT ... SELECT`, which keeps the insert independent of the delete transaction and unit-testable. Metrics: `sky_indexer_archive_seller_rows_backfilled`, `sky_indexer_archive_seller_backfill_months_done`, `sky_indexer_retention_seller_pass_parts`, `sky_indexer_retention_seller_rows`; the writers have `sky_indexer_archive_seller_rows`, `sky_indexer_scylla_import_seller_rows`.
- *Erasure and opt-out.* `dotnet SkyIndexer.dll privacy erase EXPORT.zip` (see `scripts/PLAYER-ERASURE.md`) now also erases the player from the archive when `ARCHIVE:ENABLED` and `S3:ENABLED` are set (`ArchivePlayerErasure`). Same semantics as the SQL erasure: the auctions stay, the identity is replaced like `PlayerOptOut.Anonymize` (seller/bidder id 0, fresh anonymous uuid, profile id cleared), the player's coop-member and claimed-bid entries are removed and the Scylla-only names of those rows are cleared. Order: the SQL check (incl. opt-out) runs first; then the player's auctions are located without relying on the seller index alone: `auction_sellers`/`auction_bidders` rows, the player's auctions still in MariaDB (seller id, auctioneer uuid, bids) and, for archived months without the retention-pass marker, a decode of their Scylla-sourced/merged parts matched on the uuid (one-time cost; erasure is rare), all mapped through `auction_locations`. Before anything is written every affected tag-month must be in the R2 tag index and must not have a pending Scylla import (manifest entry without `scylla_at`), otherwise the run throws with nothing changed and can be repeated after the import. Then every affected part is rewritten, uploaded and read back uncached, the part hashes in the R2 tag index and `archived_months.sha256` are updated, and only then the player's index rows are deleted; finally the SQL erasure runs (it deletes the `Players` row, the id is needed before). Any failure before the index delete keeps the index rows, a re-run continues (already anonymised parts are not rewritten, stale hashes are healed). Opt-out itself (`POST Player/optout/{uuid}`) does not delete anything, as in SQL: it stops the writers (opted-out and anonymised uuids get no seller/bidder rows) and masks the player on every archive read (`ArchivePrivacy.Mask` in the reader, so `/bids`, `/sells`, by-uuid and tag-month reads). Scope: numbered sellers/bidders on indexed auctions; coop-only or unnumbered appearances and the `ScyllaMonthManifest` hashes are not rewritten.

**Rollout order**
1. `S3__*` and `ARCHIVE__ENABLED=true` (`DELETE_MARIADB` stays false): the job archives oldest month first. Watch `sky_indexer_archive_*` (`verify_failures` must stay 0, `months_total` grows) and spot check blobs and `archived_months`.
1a. Seller index: deploy this version (the archive job applies migration `ArchiveIndexCompressionAndSellers`: it creates two empty tables and is idempotent; production already has the compression and the dropped column, so the ALTERs are metadata only). Months archived or imported from now on write their own seller rows; every month, old or new, is only marked complete by the deletion pass (step 2), which derives the rows it needs from its read-back. Nothing else to switch on.
2. `ARCHIVE__DELETE_MARIADB=true` only after the blobs and index rows are checked (the pass also reads each month's parts once to write the seller rows, see above; budget CPU and R2 reads for it, the daily month limit and `DELETE_PAUSE_MS` throttle it): months older than `WINDOW_YEARS` whose sentinel and every tag row are verified with `index_rows = rows` are deleted in batches (children, then `Auctions`, then unreferenced `NbtData`), one month per day by default. Watch `sky_indexer_retention_*`, disk, binlog and replica.
3. `OPTIMIZE TABLE` is an operator step (smallest table first, only when the table's used size fits the free disk); the worker logs each table's `data_free` after a month.
